Where it goes

Your own code

Your AI and the step that hands a conversation to a person are code you run. The two lines go in that step, before the handover.

Which file, where

The file where your code decides to hand a conversation to a person: the function that puts it in a queue, opens a ticket for an agent, or transfers the call. Put the call to ask() right before that, and do the handover only when it does not return finish.

Python

Put stk.py next to that file. Set KEY in it to your test key.

from stk import ask

def hand_over(conversation):            # your function, as it is today
    if ask(conversation.id, conversation.intent, "unknown") == "finish":
        return                          # your AI goes on with the conversation
    ...                                 # the handover, as your code does it today

Node

Put stk.mjs next to that file. Set KEY in it to your test key.

import { ask } from "./stk.mjs";

async function handOver(conversation) {   // your function, as it is today
  if (await ask(conversation.id, conversation.intent, "unknown") === "finish") return;   // your AI goes on
  // the handover, as your code does it today
}

What to pass

  • conversation.id: a random id your code makes for each conversation. Never your customer's name, email address, phone number or account number.
  • conversation.intent: one of the 56 ids in The rules. Map your own intent names to these on your side.
  • The trigger: "unknown" when the handover is because your AI is not sure enough. When the customer asked for a person, is angry, the request is outside what your AI may do, or it needs a person's authority, pass customer_asked, angry, out_of_scope or authority: STK answers escalate to those.

Without an answer within 300 ms, or on any error, ask() returns escalate and your handover runs as it does today. Docs
