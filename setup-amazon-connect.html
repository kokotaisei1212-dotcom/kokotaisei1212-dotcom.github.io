Where it goes

Amazon Connect

In the flow, an AWS Lambda function block before the transfer to the queue. The two lines go in that Lambda.

Where

  1. Make a Lambda function (Python or Node.js). Put stk.py or stk.mjs in its package, with your key.
  2. In the flow, before Transfer to queue, add the AWS Lambda function block (Integrate), Execution mode Synchronous, pointing to that Lambda.
  3. After it, Check contact attributes on $.External.decision: finish goes back to your bot; anything else, and the block's Error and Timeout branches, go on to Transfer to queue.

The Lambda (Python)

from stk import ask

def lambda_handler(event, context):
    a = event["Details"]["ContactData"]["Attributes"]       # set by your flow: the intent your bot gave
    return {"decision": ask(event["Details"]["ContactData"]["ContactId"], a.get("intent", "other"), "unknown")}

Amazon Connect waits at most 8 seconds for a synchronous Lambda; stk.py itself stops waiting for STK at 300 ms and returns escalate.

The contact id is Amazon Connect's id for the contact, not your customer's information. If you would rather not send it, pass a random id you keep with the contact.

Not known

  • The handover inside Amazon Lex or Amazon Q in Connect: not read.
