Salesforce Agentforce

In Agent Script, an action that runs before the escalation to a person, and the escalation available only when it did not return finish.

Where

  1. An Apex class that makes the request below (an HTTP callout), as an action of the agent (target apex://YourClass).
  2. In the agent's .agent file: run the action before escalating (run @actions.stk), keep its answer (set @variables.stk_decision = @outputs.decision), and make escalate_to_human: @utils.escalate available only when that variable is not finish.

The request

POST https://api.stk-evidence.com/v1/ask
X-STK-Key: <your test key, then your live key>
Content-Type: application/json

{"conversation_id": "<a random id for this conversation>", "intent": "<one of the 56 ids>", "trigger": "unknown"}

The answer: {"decision": "finish" | "escalate", ...}. Continue with your AI only on finish. On escalate, on an error, or on a timeout, transfer to a person as the flow does today.

Not known

  • Salesforce's own recipes show the escalation gated by variables, not by an action's answer: that it works with an action's answer is not shown.
  • help.salesforce.com and developer.salesforce.com could not be read on 2026-11-17. The Apex callout timeout and what happens when Omni-Channel cannot transfer: not read there.
  • The callout cannot stop at 300 ms in what was read.
